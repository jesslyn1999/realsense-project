# Bug 修复即时记录

当用户请求修 bug、debug、fix、排查异常、解决构建失败时，执行此工作流。

## 开始排查前

- 检查是否存在 `memory/bugfix_records.md`。
- 如果存在，先按模块名、报错关键字、文件名检索历史记录。
- 如果不存在，不主动创建；等需要记录时请求用户确认。

## 排查过程中

- 区分事实、推测和已验证结论。
- 未验证的根因只能标记为 `investigating`，不能写成最终结论。
- 发现可复用规避规则时，记录到本次 bug 记录的“规避规则”字段。

## 等级定义

- `S0/blocking`：阻断编译、启动、升级、通信、数据安全或核心功能。
- `S1/high`：核心功能异常、偶发严重问题、难定位问题。
- `S2/medium`：局部功能异常、边界条件、兼容性问题。
- `S3/low`：日志、可维护性、体验类问题。

## 状态定义

- `fixed`：已修复并验证。
- `mitigated`：已规避，后续仍需彻底处理。
- `investigating`：仍在调查，根因未最终确认。
- `follow-up`：当前不修，后续跟进。
- `accepted`：已确认风险可接受。

## 根因确认后

- 追加一条记录到 `memory/bugfix_records.md`。
- 记录必须包含：日期、等级、状态、模块、现象、根因、解决方案、验证方式、相关文件、规避规则、标签。
- 记录要写事实和验证结果，不写未验证推测。

## 最终回复

- 说明修复结果。
- 说明记录是否已写入。
- 标出等级、状态和记录标题。
